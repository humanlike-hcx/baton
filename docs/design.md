# Baton 实现设计

产品范围和状态只维护在 [spec](spec.md)。本文件描述当前代码的职责和约束。

## 数据流

```text
Electron 窗口 / React 界面
       │ 本机 HTTP + WebSocket
       ▼
AppState：项目、对话、队列、审批、运行记录
       │
       ├── Snapshots：运行前后内容快照、预览、冲突检查、回读恢复
       ├── Resources：显式规则、Skills、扩展、Markdown 记忆
       └── Pi 适配：持续 SessionManager、工具包装、MCP 扩展
                    │ Pi Agent 循环
                    ▼
             Gateway：唯一模型请求出口
                    │ 固定基础地址、SSE、显式鉴权
                    ▼
             用户独立运行的 Magpie
```

## 会话与运行

一个 Baton 对话持有一个持续的 Pi JSONL 路径。每次运行重新绑定项目资源、权限和 UI 监听，但使用相同的 SessionManager 文件；Pi 保存规范消息、工具结果、模型变更和压缩节点。Baton 保存的 `items` 是界面投影，不参与构造模型历史。重启时把仍在运行或排队的记录标为中断，不自动重放命令；直接执行授权恢复为询问。待投递消息留给用户确认后手动重发。

`session.prompt()` 完成后才结束运行，不以某条流式文本或单次模型回复结束为依据。取消使用 Pi abort，同时中止审批和 Baton 命令进程。插话与后续消息分别使用 Pi steer / followUp。普通消息禁止调用终端 slash 命令，Skills 通过 Pi 提示与读取工具按需使用。

## 网关与能力

`Gateway` 仅消费当前 Magpie 的 `/models`。候选必须明确报告 `tool_call: true` 和已适配的 `native_endpoints`；目前支持 OpenAI Chat Completions 与 Responses SSE。思考档位取网关字段与 Pi 支持档位的交集，不猜模型家族。未知上下文窗口在 UI 显示未知，Pi 内部使用 32768 token 的保守运行预算；未知输出上限使用 4096，已知输出上限再限制到 16384。这些是客户端预算，不是模型能力声明。

启动、保存连接或刷新目录时只请求网关的 GET /models，空闲时每分钟同步一次。目录中的适配模型默认可用，不发送逐模型推理或工具探测，也不提供单模型测试入口。设置页独立持久化 enabledModelIds，只有已勾选模型进入聊天框，空数组是有效选择。升级时沿用原有名单，后续新模型不自动勾选。更换网关地址或鉴权会重新读取目录；目录移除的模型不可继续使用。真实请求出错时按原错误路径展示，不自动换模型或重试。

Pi runtime 的所有模型请求入口（包括压缩）固定走同一 Gateway 传输。显式关闭默认配置文件与网络目录刷新，凭据存储为空实现，不让环境变量或旧登录成为自动回退。请求地址精确校验，拒绝重定向；上游错误体不直接暴露。流必须收到协议完成标记，提前断流返回失败。

用量只采纳原始上游事件中出现的数值。Pi 内部模型目录需要的零费率仅供接口构造，不作为 UI 金额；当前金额显示未知。请求模型保存在运行记录中，不推测 Magpie 内部实际账号路由。

Magpie Agent 插件只写独立的 `magpie.json`，Baton 每秒检查变化；存在运行中任务时延迟应用。连接启用时使用 Magpie 提供的 Agent 专属 key 与默认模型，关闭后恢复手动连接。格式错误明确阻止新的模型请求，不悄悄回退。连接变化取消旧目录请求，按代数丢弃旧结果；退出取消目录请求和运行并等待清理。默认模型只影响草稿，不覆盖已有 Thread.model；未勾选的外部默认模型不会绕过用户名单。

## 权限与文件

读取工具复用 Pi，包装层解析实际路径；明确启用的 Skill 目录额外获得读取权限，写权限仍只属于当前项目。文件读取与写入再次在实际操作处校验路径。修改预览或完整命令与一次审批绑定；批准后重读文件指纹，目标已变化则拒绝。拒绝、取消、超时和重复审批不能执行操作。

项目内所有运行按 FIFO 排队，包含命令、记忆写入和导入；不同项目独立。此实现也串行同项目只读运行，换取清晰的改动归属。恢复仅在项目无运行及排队任务时同步执行。

快照不依赖 Git index，使用内容寻址对象记录运行前后文件，因此保留原本的未提交修改。排除 `.git`、旧 `.baton` 和 `node_modules`；单文件上限 16MB、总内容 256MB、30000 条目，超限或无法稳定扫描时阻止可写运行。符号链接不跟随，特殊文件和硬链接阻止建立可恢复基线。恢复先检查全部变更文件，随后逐文件重验和回读；中途失败记录已恢复文件，停止后续写入。

外部编辑的归属不能靠文件快照完全判定。工具前后观察到无关变更时禁用自动恢复。命令、MCP 或扩展实际改变了项目文件时，由于无法可靠归属到具体写入目标，也会阻止自动恢复；文件 diff 仍可查看。命令、扩展和 MCP 的数据库、网络、环境变化不在快照恢复范围内。

## 规则、记忆、扩展和 MCP

项目发现只列出根 `AGENTS.md`、`.baton-v2/{rules,skills,extensions}` 及 Baton 的 `v2/resources`。手动添加绝对路径后也默认停用；用户明确启用后才交给 Pi 资源加载器。规则按列表顺序进入 Pi agent files；停用在下次运行生效。

项目记忆为 `.baton-v2/memory/*.md`，Agent 通过 memory_list 按需读取，write/delete 使用同一审批和快照。没有后台提炼、全局检索或跨项目自动共享。

无终端 UI 扩展必须附带 `<extension-file>.baton.json`，声明 `{ "host": "baton-v2", "ui": "none" }`。声明只是兼容约束，不是安全认证；代码变化后需再次确认。扩展不能覆盖受保护的基础工具，调用其工具须通过权限钩子。依赖终端 UI 的扩展返回明确错误。

MCP 复用 `createMcpExtension`，配置来源替换为 Baton 明确保存的服务列表，使用 direct tool exposure。不会扫描其他应用的配置。MCP 工具全部按外部工具审批，自报只读也不例外；只读会话不开放它们。`/mcp` 仅由设置中的连接检查触发，用于状态和工具列表，不请求模型。每次会话关闭显式发出 session_shutdown，等待服务断开后 dispose。

## 桌面与本机服务

Electron 仅载入 127.0.0.1 本地界面，关闭 Node integration、开启 contextIsolation 和 renderer sandbox。外部链接交给浏览器。Electron 单实例锁、数据目录独占锁和端口占用错误分别处理。数据锁在加载和修改历史之前取得；异常退出后只回收已不存在的进程锁。关闭所有窗口即退出，先取消并保存自身运行，不关闭独立 Magpie。

服务拒绝非本机 Host、跨站 Origin 和缺少自定义请求头的写请求。开发服务器的 47320 Origin 是唯一额外白名单。网页只作为开发入口。桌面构建支持 `--platform=darwin|win32` 与 `--arch=arm64|x64`；构建产物不等于对应平台真实验收。

## 普通聊天与项目折叠

US-132 的普通聊天使用无 projectId 的 Thread，同样保存 Pi 会话；内部只创建会话元数据 cwd，不加入项目列表。Pi 不注册基础文件/命令/记忆工具、MCP 或项目扩展，不加载项目规则与 Skills。各普通聊天独立排队；压缩、取消、模型切换和用量复用现有路径。项目能力接口对无项目对话明确拒绝。

US-131 的折叠状态以项目 ID 保存在本机界面偏好，隐藏列表不改变当前选择、后端任务或历史。鼠标与键盘均可展开。

桌面打包显式设置 Pi 的 PI_BUNDLED_NODE 编译标记，使用 SDK 内嵌 jiti/虚拟模块加载扩展。每次构建先从打包文件加载一个包含 typebox 导入的 TypeScript 扩展并验证 session_start 通知，避免源代码测试通过而桌面包丢失动态依赖。

## 草稿、模型菜单与归档

首页默认是未绑定项目的草稿；切项目只更改草稿归属。`POST /api/threads/start` 先验证消息、模型和权限，再创建 Thread 并提交首条消息。普通新建不调用创建接口。侧栏过滤历史遗留的空记录。已有会话的草稿按 ID 存在 Shell，切设置/会话保留，发送成功后条件清空；刷新或退出不会持久化未发送文本。

模型名和强度共用一个 Popover。面板中的模型名切换到模型列表，选择后关闭；推理滑块仅使用网关已确认档位，拖动预览、松开后提交，键盘支持同样的提交行为。过渡只用 opacity/transform，不动画尺寸，不移动 anchor；遵循 prefers-reduced-motion。

归档写入 Thread.archivedAt，活动任务须先停止。正常列表不返回归档正文，归档列表只返回标题等元信息；恢复后继续原 Pi 会话。归档不删除会话文件或项目文件，也不撤销运行改动。已移除项目须重新打开后恢复其归档。保留历史的归档语义参考 [Cursor 的说明](https://prod.cursor.com/help/ai-features/side-chats#how-do-i-close-or-archive-a-side-chat)。
