# Baton 项目规格说明

更新日期：2026-11-04。产品方向：**以 Pi 为基座，通过独立运行的 Magpie 使用模型的桌面编程 Agent。**

本文规定当前要做什么、职责如何划分、怎样验收。它整体替代旧规格，不再将过时方案和当前需求混在同一份正文中。历史版本通过 Git 历史查阅。

**当前已按新架构重写实现，并完成 macOS、真实 Magpie 和自动化验证。Windows 真实桌面验收保留待办（用户确认暂无环境）。** 逐项证据见第 8 节；不能把构建成功当作 Windows 桌面验收。后续用户要求的项目折叠、普通聊天和归档纳入 US-131～US-133。

## 1. 产品目标

Baton 是个人使用、运行在本机上的普通桌面编程 Agent。首版同时面向 macOS 和 Windows。

用户可以不选择项目直接普通聊天；需要操作文件时，打开项目、创建对话、选择模型，便能通过自然语言让 Agent 理解代码、搜索文件、修改代码、运行命令和测试，并查看执行过程与文件变化。用户可以补充要求、停止运行、切换模型，以及在重启应用后继续对话。

产品围绕一个主 Agent 的普通对话展开。测试、代码审查和问题修复都可以作为普通对话任务执行；不要求进入额外的检查阶段，也不要求先填写任务卡或验收表。

首版成立的标准是：用户能在两个目标系统上通过桌面应用稳定完成真实编程任务，理解 Agent 做了什么，并控制和恢复其文件改动。

## 2. 职责边界

```text
Baton 桌面界面
    ↓ 对话、权限选择、工具过程、文件改动
Baton 本地应用层 + Pi SDK
    ├─ Pi：执行循环、会话、上下文压缩、基础工具、资源扩展机制
    └─ Baton：项目管理、审批、记忆入口、改动记录和恢复、桌面适配
    ↓ 模型请求
独立运行的 Magpie
    ↓ 账号、供应商协议与请求路由
模型服务
```

| 部分 | 负责 | 边界 |
|---|---|---|
| Pi | 模型与工具循环、运行事件、消息排队、取消、会话存储与恢复、上下文压缩、基础编程工具、Skills 和扩展接口 | 不直接决定 Baton 的桌面交互、长期记忆产品规则、权限档位或首版范围 |
| Magpie | 供应商登录与凭据、供应商协议适配、模型接入和请求路由 | 用户独立安装和管理；Baton 不安装、启动、停止或更新 Magpie |
| Baton | 桌面交互、项目与对话组织、Magpie 连接配置、模型选择、审批、文件改动与恢复、项目记忆、资源配置和状态展示 | 不再自建供应商代理，不再调用其他厂商的 Agent CLI 充当执行器 |

### 2.1 Pi 的复用范围

- 复用 Pi SDK 的执行循环；Baton 消费事件并提供桌面操作，不另写一套模型—工具循环。
- 一个 Baton 对话对应一个持续保存的 Pi 会话。Baton 维护项目归属、标题等应用信息，Pi 维护消息、工具记录与压缩状态。
- 复用 Pi 的会话恢复和上下文压缩，替换旧版“每次新建会话，再拼入截断摘要”的续聊方式。
- 默认复用 Pi 的读取、搜索、编辑、写入、命令执行等基础工具；明确无法满足产品要求的工具才适配或替换。
- 复用 Pi 的 Skills 加载机制和扩展接口。SDK 中需要显式接入的能力应完成适配，不能把 CLI 默认行为当作 SDK 已自动具备的功能。
- 通过适配层对接 Pi；实现时以项目锁定版本的真实接口为准。升级 Pi 需要验证会话、事件、工具和扩展兼容性。

### 2.2 Magpie 的接入范围

- Baton 配置 Magpie 地址和连接所需的鉴权信息，提供连接状态、模型列表与错误提示。
- 只展示当前接入链路中已确认可用的模型及参数。协议、模型能力和工具调用兼容性必须验证，不能只凭模型名字推断。
- 模型由用户手动选择和切换。Baton 不按成本、任务难度、失败次数自动换模型，也不静默退回供应商直连。
- Pi 的默认供应商配置、环境变量或其他 CLI 登录不能绕过 Magpie 自动生效；Baton 仅向模型运行时提供已配置的网关连接。网关鉴权信息与供应商凭据是不同的配置。
- Magpie 内部的账号和路由策略由 Magpie 管理。Baton 不承诺看见网关内部的全部路由信息；只记录能够确认的请求模型与返回信息。
- 流式文本、工具调用、取消、错误和重试行为都属于集成验收范围。“连接成功”不代表整个 Agent 链路可用。
- 不要求首版支持 Magpie 提供的所有协议或模型；采用经验证可用的接入组合，并说明已验证范围。

## 3. 首版使用流程

1. 用户先在独立 Magpie 中完成模型服务配置，在 Baton 中设置连接。
2. 打开本地项目，确认要启用的项目资源，创建对话并选择模型。
3. 输入任务。Agent 使用 Pi 工具读取代码，按当前权限申请或执行修改与命令。
4. 界面实时呈现回复、工具调用、命令结果和审批；用户可以补充指令或停止运行。
5. 用户可以继续要求运行测试、解释错误或修改代码。验证结果来自实际工具执行，不能仅凭模型措辞显示成功。
6. 用户查看某次运行的文件 diff，必要时预览并撤销这次文件改动。
7. 同一对话可手动切换模型继续；关闭应用后重新打开，可恢复已保存的历史。

**不设置专门的“让另一个模型检查”按钮、独立检查会话、自动修复循环或检查阶段状态机。** 普通对话中仍可要求模型检查代码和运行测试。

## 4. 用户故事与验收标准

新故事从 US-105 开始，避免与旧版 US-1～US-104 混淆。状态依据本轮实现与实际证据更新；平台未覆盖部分在对应条目和第 8 节单列。

状态维护规则：

- **未按新规格验收**：尚未确认符合本文，可能需要新实现、迁移或重新验证。
- **实现中**：正在适配，尚未完成所需验证。
- **待真实验证**：实现和适用的自动化检查已完成，仍缺真实网关、真实任务或目标系统验证。
- **完成**：对应验收标准已满足，并记录测试或人工验证证据及其环境。

### 4.4 工具与权限

| 编号 | 用户故事与验收标准 | 状态 |
|---|---|---|
| US-114 | 我能使用 Pi 的基础编程工具，并看到输入、结果、命令退出码与错误。必要的工具适配不得跳过 Baton 的审批和改动记录；输出截断需明确说明，不能因此把命令失败报告为成功。 | 完成（证据见 §8） |
| US-115 | 我能为当前对话选择“只读／询问／直接执行”，默认询问。直接执行授权只对当前对话有效，重启后收回并回到询问；不自动传播给其他对话或项目。 | 完成（证据见 §8） |
| US-116 | 需要批准时，我能看到目标路径、修改预览或完整命令，选择允许或拒绝。拒绝、取消或失效的审批不能继续执行；已变更的操作不得套用另一项操作的批准。 | 完成（证据见 §8） |

权限的具体含义：

- **只读**：只开放经确认适合该模式的读取能力，不开放通用命令执行、文件修改或未确认只读的外部工具。只读限制作用于 Baton 管理的工具调用，不等于对整个宿主进程实施隔离。
- **询问**：修改文件、运行命令及外部工具的相关副作用在执行前审批；可安全读取的工具无需逐次询问。
- **直接执行**：在用户已经授权的对话和访问范围内执行，无需逐次审批；不等于开放所有路径或其他项目。
- 普通文件工具仍需校验访问范围和链接后的实际路径，避免仅依靠提示词约束。外部工具的能力声明不视为已证实的安全保证。
- 首版使用应用层审批与工具限制。命令及已启用扩展运行在用户本机权限下，**不承诺操作系统级沙箱、进程隔离或完整网络隔离**。
- 扩展可能直接执行代码，MCP 服务可能拥有自身权限；启用它们代表信任相应执行组件，不能把工具审批宣称为对所有程序代码的隔离。

恢复范围是能够可靠追踪的本地项目文件。文件恢复不撤销数据库更新、已发送请求、已安装依赖的所有环境变化或其他外部副作用，也不回退模型的隐藏状态。运行期间发现外部编辑或无法确定改动归属时，不承诺自动安全撤销。

本版的 MCP 是 **Baton 作为客户端使用外部工具**。旧版为 Cursor／其他 Agent 暴露 Baton 工具的 MCP 服务和 CLI 桥接不再属于产品方案。

复用其他应用的 Skill 时，文件格式兼容不等于其所需工具、路径和交互都兼容；缺少依赖应明确报告。首版不做插件市场、自动安装任意第三方代码或全面兼容所有 Pi／Codex／Claude 扩展的承诺。

## 5. 验证策略

### 5.1 自动化验证

- 测试对外行为：对话事件、工具结果、文件变化、审批、会话恢复、连接错误和桌面启停；避免只验证某个内部函数被调用。
- 沿用现有本地 API 作为应用层主要测试入口，配合隔离的临时工作区和数据目录。
- 模型侧使用可控的 Pi 假模型和 Magpie 接入契约替身；外部工具使用可控 MCP 替身。替身通过只能证明客户端行为，不能替代真实网关与供应商兼容验收。
- 删除依赖旧产品方案的 Cursor ACP、供应商登录和独立检查流程测试；保留仍然有意义的回归覆盖。
- 重点覆盖拒绝与取消、重复或失效审批、断流、工具失败、切换模型、压缩失败、恢复冲突、并行项目事件归属和退出后重启。
- Windows 的命令、路径、进程清理与文件权限行为必须验证；同时维护 macOS 相关行为的验证证据。
- 代码实现提交前运行仓库要求的类型检查和测试，后续根据实际桌面构建补齐适用检查。

### 5.2 真实任务验收

以下全部满足，才能称首版完成：

1. 在 macOS 和 Windows 上分别从桌面入口启动，并连接用户已配置的独立 Magpie。没有网关时提示可理解，Baton 不转而读取旧供应商账号。
2. 在真实项目执行一次“读取代码—修改文件—运行测试—根据结果继续”的完整任务。验证命令及退出码有真实记录，不能用演示回复代替。
3. 选用至少两个经 Magpie 接入的可用模型，在同一对话中手动切换，验证前文及必要工具结果能继续使用；记录实际模型和接入组合，不据此宣称兼容全部模型。
4. 对持续会话进行保存、重启恢复和一次压缩验证；验收任务中的重要约束和下一步能继续使用。说明压缩和模型切换的实际边界：摘要仍可能丢失细节，保存完整记录不代表每轮发送全部历史，也不保证跨模型迁移隐藏推理状态。
5. 验证三档权限、批准与拒绝、取消、直接执行授权在重启后失效，以及扩展和 MCP 的权限边界。
6. 打开两个项目并行运行，再在同一项目发起两个写任务，确认排队、审批和结果归属正确。
7. 在项目已有未提交修改的条件下完成一次新增改动、查看 diff 和撤销；再制造后续编辑冲突，确认不会覆盖后续工作。
8. 明确保存一条项目记忆，在该项目新对话读取；另一项目不默认获得它。修改、删除和停用资源后验证实际生效情况。
9. 启用一个明确兼容的 Skill／扩展，并连接一个测试用 MCP 服务，分别验证成功、拒绝或失败路径。
10. 退出应用后确认 Baton 进程与资源正常释放，Magpie 仍独立运行。重启后历史可见，未完成任务不被误报完成或自动重放。
11. 新版启动后旧会话、规则、记忆及凭据文件仍保留；只导入用户明确选择的规则和记忆。

这是新架构的实施顺序，不是已完成情况或工期承诺。两个桌面平台都属于首版，不能只完成 macOS 就把首版标为完成。

| B：完成日常使用 | 多项目与排队、文件 diff／撤销、项目规则与显式记忆、选定 Skills／扩展、MCP、界面与用量适配 | US-112～US-125 |

## 7. 明确不做

- Baton 自有供应商代理、供应商 OAuth／API key 管理、Codex 登录复用，以及供应商模型家族过滤策略。
- Cursor ACP、Claude Code／Codex CLI／Gemini CLI 等独立 Agent 执行器；旧的对外 MCP／CLI 工具桥接。
- Magpie 的内置安装、托管运行和更新管理；Baton 自动按成本或难度选模型、自动升级或切换模型。
- 专门的跨模型检查按钮和独立检查会话、自动顾问、子 Agent、角色卡片、自动接力及固定阶段状态机。
- 自动修复—复检闭环、强制检查命令配置、跨模型家族的评审限制、评审通过率和接力统计。
- 全局或跨项目自动共享记忆、后台提炼全部对话、自动教训积累、专门的上下文整理 Agent、向量数据库。
- 同一项目的多个写任务同时修改同一工作副本、自动 worktree 管理。
- 全面代码编辑器、插件市场、项目管理看板、多人协作、聊天软件集成、大型统计后台。
- 系统级沙箱或容器隔离、撤销外部系统副作用、回退聊天节点并自动恢复全部环境。
- 正式独立网页版产品线、代码签名／公证和自动更新。

用户日后提出这些需求时，应先明确问题与验收条件，再新增故事；不因旧版曾存在相关实现而自动恢复。
