# Baton 项目规格说明（spec）

本文档是 Baton 整个项目的完成指导：要做什么、做到什么程度算完成、现在做到哪一步。实现方式见 `docs/design.md`；两者冲突时以本文档为准。

**状态标记**（每条用户故事都有）：

- **完成**：已实现，并有自动化测试或已通过手动验收清单。
- **待验证**：代码已写，但还没有自动化测试，或还没在真实环境里验证。
- **未做**：还没有实现。
- **暂缓**：明确推迟，写有触发条件，满足条件再做。

一条故事只有在有自动化测试或手动验收步骤之后，才能标为「完成」。

## 问题

我已经在为几家 AI 订阅付费：ChatGPT、Cursor，以及按量付费的 DeepSeek。它们各自是一个孤岛：

- 每个工具有自己的上下文和记忆。在一个工具里讨论出的结论，换到另一个工具就得重新解释一遍。
- 想让一个模型出方案、另一个模型写代码、再换一个模型审查，只能我自己在几个窗口之间复制粘贴，还得记住谁做了什么、改了哪些文件。
- 让模型互相直接接力又不放心：没有规则约束，就可能自己审自己、在同一个问题上来回打转，或者悄悄把额度花光。
- 很多「多 agent 平台」要求接入 API key，但我已经有订阅，不想再为同样的模型按量付费。

## 方案

Baton 是一个跑在我自己电脑上的个人 agent 工作台。Pi 是引擎，Cursor 的模型通过官方 Cursor Agent CLI 接入。

- **用订阅登录，不用 API key**：GPT 系模型通过 ChatGPT 登录使用；Cursor 订阅里的非 GPT 模型通过 Cursor CLI 使用；DeepSeek 是唯一用 API key 的例外。每个模型家族只有一条接入路线：GPT 不会在 Cursor 里重复出现，也不提供 Auto。
- **一个 agent = 角色 + 运行时 + 账号来源 + 具体模型**：Cursor 里的每个模型是独立的 agent，不笼统地叫「Cursor」。
- **共享一切**：所有 agent 读写同一个工作区里的同一批文件，共用同一份房间上下文、记忆、教训和规则，使用同一套工具。
- **两种线程**：
  - **对话线程**：选一个 agent 直接聊，随时换 agent 接着聊，新 agent 能接上前面的内容。这是日常使用的主要方式。
  - **接力线程**：一件需要验收的事，按「方案 → 实现 → 检查 → 完成」推进，由 Baton 按规则挑选每一棒的 agent，不让 agent 之间自由传球。
- **规则约束接力**：检查者不能和实现者属于同一模型家族；交接次数、退回次数、空转次数和额度都有上限；检查命令失败时不能判通过；关键节点停下来等我确认。
- **一切可见、可撤销**：每个 agent 启动时收到了什么都能查看；每次写文件前自动快照，可以看 diff、一键回滚。

### 阶段

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **P1 本地可用** | 本地网页 + 本地服务，三条账号路线，对话线程和接力线程 | 见下方「P1 完成线」 |
| **P2 桌面应用** | 用 Electron 打包同一套服务和界面 | 双击 `.app` 就能用，不需要终端；关掉窗口时服务也停止；界面和网页版是同一套 |
| **P3 更多 agent** | 接入 Claude Code、Gemini CLI、Codex CLI 等 | 第一个新 agent 接入时，不需要改路由、编排和界面主体；同一模型家族的路线可以在设置里切换 |

按 P1 → P2 → P3 顺序推进，前一阶段达到完成标准后才开始下一阶段。

**P1 完成线**（全部满足才算 P1 完成）：

1. 三条账号路线都用真实账号登录成功：ChatGPT 登录、DeepSeek key、Cursor CLI 登录。
2. 对话线程：在一个对话线程里先后和三条路线上的 agent 各聊至少一轮。换 agent 后，新 agent 能正确引用前面讨论的内容；对话里记下的记忆，在另一个线程里能被检索到。
3. 接力线程：用真实账号，在任意一个目录里跑完一个完整线程：GPT 出方案 → 我确认 → DeepSeek 或 Cursor 里的某个模型实现 → 检查命令通过 → 另一模型家族审查通过 → 我确认完成。整个过程不需要手动改 `.baton/` 里的任何文件。任务内容不限，写文档、整理资料都可以。
4. 自动化测试全部通过，GitHub Actions 在每次推送时运行并通过。
5. 「测试决策」里的手动验收清单全部通过。

### agent 定义

10. **US-10**（P1 · 完成）作为我，我想让每个 agent 由「角色 + 运行时 + 账号来源 + 具体模型」组成，Cursor 里的每个模型都是独立的 agent，以便清楚地知道每一棒是谁在干活。
11. **US-11**（P1 · 完成）作为我，我想在新建或编辑 agent 时只能选这条路线允许的模型，违反「一个家族一条路线」时保存会被拒绝并说明原因，以便配置不会出错。
12. **US-12**（P1 · 完成）作为我，我想给每个 agent 分别设置写文件、运行命令、联网的权限（允许 / 每次问我 / 禁止），以便按信任程度区别对待。
13. **US-13**（P1 · 完成）作为我，我想给每个 agent 设成本档位，以便条件相同时 Baton 优先选便宜的。
14. **US-14**（P1 · 完成）作为我，我想停用一个 agent 而不删除它，以便临时不让它参与。
15. **US-15**（P1 · 完成）作为我，我想查看某个 agent 以某个角色启动时实际收到的启动上下文：每段的来源和大小、重复的内容、整体的哈希，以便排查它为什么表现不好。
16. **US-16**（P1 · 完成）作为我，我想让担任顾问的 agent 必须只读，以便顾问只出主意、不直接动手。

### 对话线程

17. **US-17**（P1 · 完成）作为我，我想新建一个对话线程，选一个 agent 直接聊，不需要填验收标准，以便日常提问、讨论方案、让它读代码。
18. **US-18**（P1 · 完成）作为我，我想在对话中途换一个 agent 继续，新 agent 能看到前面的对话（较早部分的摘要加最近几轮原文），以便让不同模型接着同一个话题往下聊。
19. **US-19**（P1 · 完成）作为我，我想让对话线程默认只读，需要时我能给这个线程临时开放写权限，写之前照常自动快照，以便聊着聊着也能顺手改文件，而且随时能撤销。
20. **US-20**（P1 · 完成）作为我，我想让对话里的 agent 能读房间上下文、检索和写入共享记忆，以便在对话里形成的结论，其他线程和其他 agent 也能用上。
21. **US-21**（P1 · 完成）作为我，我想在对话里实时看到回复、工具调用和审批请求，以便和接力线程有一样的可见性和控制力。
22. **US-22**（P1 · 未做，不算完成线）作为我，我想把一段对话一键转成接力线程，自动带上已讨论出的任务和验收标准，以便讨论清楚之后直接交给接力流程去做。

### 接力线程

23. **US-23**（P1 · 完成）作为我，我想新建接力线程时必须填标题和至少一条验收标准，并可以选起始阶段和指定第一棒 agent，以便每件事都有明确的完成判断。
24. **US-24**（P1 · 完成）作为我，我想让接力线程按「方案 → 实现 → 检查 → 完成」推进，检查不通过时只能退回实现，以便流程清楚、不乱跳。
25. **US-25**（P1 · 完成）作为我，我想让 agent 只能提议下一阶段，由 Baton 决定交给谁，以便接力受规则约束，而不是 agent 之间自由传球。
26. **US-26**（P1 · 完成）作为我，我想让 Baton 按「承担该角色 → 权限满足 → 账号可用 → 额度未用完 → 成本从低到高」挑选 agent，也可以由我为某个阶段指定 agent，以便默认省钱、需要时我说了算。
27. **US-27**（P1 · 完成）作为我，我想让检查者和实现者永远不属于同一个模型家族，以便不会出现自己审自己。
28. **US-28**（P1 · 完成）作为我，我想在「方案 → 实现」之前和「标记完成」之前停下来等我确认，并能在设置里把这两个节点改成自动，以便关键决定由我来做。
29. **US-29**（P1 · 完成）作为我，我想在下一棒需要比之前更高的权限时停下来等我批准，以便权限不会在接力中悄悄升级。
30. **US-30**（P1 · 完成）作为我，我想给每个线程设交接次数、退回次数、连续空转次数和各账号额度的上限，超过任何一项就暂停，由我决定是否继续，以便不会无限打转或把额度花光。
31. **US-31**（P1 · 完成）作为我，我想让同一个工作区同一时间只有一个会写文件的运行，其他写运行排队，以便多个 agent 不会同时改同一批文件。
32. **US-32**（P1 · 完成）作为我，我想在线程运行时随时插话，插话作为下一次运行的补充说明，以便中途纠正方向。
33. **US-33**（P1 · 完成）作为我，我想随时取消正在进行的运行，以便及时止损。
34. **US-34**（P1 · 完成）作为我，我想在第二次退回、同类问题反复出现、或出方案之前，让一个只读、干净上下文的顾问给出建议（机械事实、我的判断、我希望听到的答案三栏），建议附在确认卡上由我决定，以便卡住时有一个独立视角。
35. **US-35**（P1 · 完成）作为我，我想在服务重启后看到原本在运行的线程被标为暂停，而不是丢失，以便能接着做。
36. **US-36**（P1 · 完成）作为我，我想在线程的时间线里实时看到流式输出、工具调用、审批、交接、检查结果和顾问意见，以便随时知道每一棒在做什么。

### 上下文与预算

37. **US-37**（P1 · 完成）作为我，我想让每次运行的启动上下文按固定顺序拼装（通用规则、角色规则、运行时规则、agent 职责、房间上下文、置顶记忆、线程摘要与最近交接、文件变化、任务卡），以便每个 agent 都在同样的共识上开工。
38. **US-38**（P1 · 完成）作为我，我想在启动上下文超过预算时拒绝启动，并指出是哪一段超了，以便不会被悄悄截断。
39. **US-39**（P1 · 完成）作为我，我想让每次运行记录启动上下文的哈希和原文，以便事后还原「它当时看到的是什么」。
40. **US-40**（P1 · 完成）作为我，我想在界面里编辑房间上下文（`CONTEXT.md`，有大小上限），agent 也能用工具维护它，以便项目背景和约定只写一处。
41. **US-41**（P1 · 完成）作为我，我想在 Pi 压缩一次运行内的对话时，把摘要里的进展同步到交接草稿，以便长任务被压缩后交接不丢内容。
42. **US-42**（P1 · 未做，不算完成线）作为我，我想在房间上下文超预算时由 DeepSeek 自动整理（合并重复、把细节移进记忆），改动有 diff、可撤销，以便房间上下文保持精简。
43. **US-43**（P1 · 完成）作为我，我想让 agent 之间不传原始对话，只传交接记录和线程摘要，以便每一棒的上下文干净、可控。

44. **US-44**（P1 · 完成）作为我，我想让记忆分为事实、决定、偏好三类，只追加不覆盖，修改时用「取代」并保留旧条目，以便能追溯每条结论的来历。
45. **US-45**（P1 · 完成）作为我，我想让写入记忆前自动查重，与已有条目高度相似或超过长度上限时拒绝写入，以便记忆不膨胀。
46. **US-46**（P1 · 完成）作为我，我想让置顶记忆注入每次启动上下文，其余记忆由 agent 按需检索，以便重要约束不会被忘记，又不浪费上下文。
47. **US-47**（P1 · 完成）作为我，我想在界面里添加记忆、置顶或取消置顶、标记过时、按关键词筛选，以便我也能直接维护共享记忆。
48. **US-48**（P1 · 完成）作为我，我想能关闭某个工作区的记忆，以便在不需要的项目里不产生记忆。
49. **US-49**（P1 · 完成）作为我，我想让每次运行结束时都写交接（做了什么、改了哪些文件、还剩什么、建议下一步、检查结论），漏写时先追问一次，再自动生成并标明「自动生成」，以便下一棒总能接上。
50. **US-50**（P1 · 完成）作为我，我想让反复出现的问题记成教训并累计次数，第二次出现时提醒我把它固化成规则、检查命令或测试，并能标记固化到了哪里，以便同一个坑不踩第三次。
51. **US-51**（暂缓）作为我，我想让记忆检索使用全文索引，以便记忆很多时检索仍然又快又准。触发条件：记忆超过 500 条，或检索明显变慢。

### 工具

52. **US-52**（P1 · 完成）作为我，我想让所有 agent 使用同一套工具定义：Pi 里的 agent 直接调用，Cursor 里的 agent 通过 Baton 的 MCP 服务或 `baton` 命令行调用，权限判断完全一致，以便无论哪条路线，行为都一样。
53. **US-53**（P1 · 完成）作为我，我想让 GPT 系模型用补丁格式改文件、其他模型用文本替换，以便每个模型都用它最擅长的编辑格式。
54. **US-54**（P1 · 完成）作为我，我想让负责实现和检查的 agent 拿不到挑选下一棒的工具，只能在交接里写建议，以便接力权留在 Baton 手里。
55. **US-55**（P1 · 完成）作为我，我想让运行命令的工具单独返回退出码，输出过长时保留开头和结尾、只截掉中间，并保留错误输出，以便 agent 能正确判断命令成败。
56. **US-56**（P1 · 完成）作为我，我想在时间线上看到每次工具调用大约占用多少 token，以便发现浪费上下文的调用。

### 权限与安全

57. **US-57**（P1 · 完成）作为我，我想让 agent 只能访问工作区内的文件，越界路径、符号链接逃逸和禁止路径（如 `.env*`、`.git/`、凭据文件）一律拒绝，`.baton/` 只能通过专用工具写入，以便 agent 碰不到不该碰的东西。
58. **US-58**（P1 · 完成）作为我，我想让命令按「黑名单 → agent 自己的禁止 → 白名单（仅限不含管道、重定向等符号的简单命令）→ agent 自己的允许 → 问我」的顺序判断，以便常用的安全命令不用每次确认，危险命令永远不能执行。
59. **US-59**（P1 · 完成）作为我，我想让审批卡显示完整命令或改动预览，超时未处理视为拒绝，以便在知情的情况下做决定。
60. **US-60**（P1 · 完成）作为我，我想让 Cursor 的每个权限请求都转到 Baton 的审批流程，只读角色不能改文件，启动 Cursor 时不使用跳过确认的参数，以便 Cursor 里的 agent 和 Pi 里的 agent 受同样的约束。
61. **US-61**（P1 · 完成）作为我，我想让「联网」策略管住 agent 自带的联网工具：Cursor Agent 自带的联网请求按 agent 的联网策略处理；Pi 里的 agent 没有联网工具，只能通过运行命令联网，由命令审批管住，以便联网行为都在我的控制之下。
62. **US-62**（P1 · 完成）作为我，我想让凭据只存在本机（权限 0600），不出现在任何 API 响应里，也不进入 agent 运行命令时的环境变量，以便凭据不会泄露给浏览器或模型。
63. **US-63**（P1 · 完成）作为我，我想让本地服务只监听本机，校验 Host 和 WebSocket 的 Origin，所有写操作都要求 `X-Baton` 请求头，以便其他网页和局域网里的设备无法操纵 Baton。
64. **US-64**（P1 · 完成）作为我，我想让所有数据（线程、记忆、凭据、日志）只存在我的电脑上，不做任何统计上报；Baton 自己只连接模型服务商和 Cursor CLI，以便我的代码和对话不会流向别处。
65. **US-65**（P1 · 完成）作为我，我想让每次工具调用和审批都写入审计日志，以便事后查清谁在什么时候做了什么。

### 检查

66. **US-66**（P1 · 完成）作为我，我想为工作区配置检查命令（测试、类型检查、lint 等），检查阶段先跑这些命令，再交给模型审查，以便「通过」有客观依据。

## 实现决策

- **模块划分**（沿用现状）：
  - **核心引擎**：工作区存储、启动上下文拼装、记忆/交接/教训、工具注册表、权限、命令执行、影子 git 快照、补丁解析、检查、路由、执行器、编排。
  - **本地服务**：HTTP + WebSocket API、登录流程、凭据存储、审批转发。
  - **MCP 服务与 `baton` 命令行**：都通过本地服务的工具桥调用核心工具，不直接读写工作区状态。
  - **网页界面**：只通过 HTTP 和 WebSocket 与本地服务通信。这条是 P2 桌面版能直接复用界面的前提。
- **执行器**：Pi 执行器负责 ChatGPT、DeepSeek 和离线演示模型；ACP 执行器负责 Cursor Agent，以后也负责其他支持 ACP 的命令行 agent；演示执行器使用 Pi 的假模型。新增执行器时只需实现统一的执行器接口，并发出统一的运行事件。
- **路线规则**：模型家族由模型标识推导；每个账号来源只允许特定的运行时和服务商组合；P1 的路线是固定的。P3 时改成「每个家族一条生效路线，在设置里选择」，路线校验和模型列表过滤都按这个设置执行。
- **线程类型**（新增）：线程增加「类型」字段，取值为「接力」或「对话」。
  - 接力线程沿用现有的阶段状态机和路由。
  - 对话线程不经过路由和阶段状态机：我的每条消息触发一次运行，由我当前选中的 agent 执行。
  - 对话线程新增一个「对话」角色，对应一份角色规则：默认只读，可以使用上下文、记忆和读文件类工具，不提供挑选下一棒的工具。
  - 对话线程可以由我临时开放写权限，复用现有的「已批准权限级别」机制；写运行同样受「一个工作区同时只有一个写运行」约束，并且写之前快照。
  - 换 agent 时，新 agent 的启动上下文包含对话的滚动摘要和最近几轮原文，复用接力线程的「线程摘要 + 最近交接」机制。对话的每次运行也生成交接记录。
  - 发消息的 API 增加可选的「agent」参数，表示用哪个 agent 回复；新建线程的 API 增加「类型」参数。对话线程不要求验收标准。
  - 转成接力线程：新建一个接力线程，任务和验收标准由当前 agent 根据对话整理后交给我确认，两个线程互相保留链接。
- **硬规则的上限**：所有上限（交接次数、退回次数、空转次数、各账号额度、启动上下文预算、审批超时）都可以在设置里调整。默认值只写在代码的默认配置里，本文档不写具体数值。
- **联网控制**：「联网」策略只作用于 agent 自带的联网工具，P1 中即 Cursor Agent 的联网请求。Baton 不给 Pi 里的 agent 提供联网工具；命令行里的联网归命令审批管。
- **凭据**：凭据只存在本机的 Baton 数据目录，文件权限 0600；服务启动时从环境中移除 `OPENAI_API_KEY`；agent 运行命令时的环境变量去掉所有疑似凭据的变量。
- **数据位置**：工作区状态在工作区的 `.baton/` 目录；全局数据（凭据、设备标识、最近工作区、演示工作区）在 `~/.baton`，可以用环境变量改到别处。
- **可测试性改造**（新增）：本地服务的状态对象需要能在测试里注入数据目录、工作区、Cursor 命令和执行器配置，使测试可以在进程内构造完整服务而不监听端口。

## 测试决策

- **好测试的标准**：只测外部行为，即 API 的输入输出、工作区里文件的变化、线程时间线和状态，不测内部函数怎么实现。重构内部实现时测试不应该需要改。
- **唯一主切面：本地 HTTP API**。测试在进程内直接调用服务的 API，不监听真实端口，从新建线程一路测到完成。这一层覆盖：
  - 接力规则和对话线程；
  - 权限与审批；
  - 登录状态（用替身模拟登录结果）；
  - 安全要求：Host 校验、写操作必须带 `X-Baton` 请求头、任何响应里都不出现凭据。
- **外部依赖的替身**（沿用现有的两个）：Pi 的假模型代替 GPT 和 DeepSeek，模拟的 Cursor CLI 代替真实的 Cursor。每个测试用独立的临时工作区和临时数据目录。
- **保留的单元测试**：路由、权限路径判断、命令策略、补丁解析、模型家族、记忆查重、启动上下文拼装、检查结果分类等纯逻辑，保留现有单元测试，不再新增其他切面。
- **迁移**：HTTP API 切面已建好（`apps/server/test/`，辅助工具 `testServer()` 在进程内构造服务），新测试都写在这一层。编排层原有的端到端测试保留，以后逐步上移。
- **已有可参考的测试**：演示流程端到端测试、模拟 Cursor 的 ACP 测试、核心单元测试，以及共用的测试辅助工具（临时目录、自动审批、等待线程稳定）。
- **CI**：GitHub Actions 在每次推送时运行类型检查和全部测试。
- **手动验收清单**（真实账号部分无法自动化，P1 完成前逐项走一遍并记录结果）：
  1. 在 Mac 上从零运行 `pnpm install` 和 `pnpm dev`，打开界面，演示工作区自动就绪。
  2. 用演示 agent 跑完一个接力线程，再跑一个任务里含「退回」的线程，确认会退回重做；查看一次改动 diff，做一次回滚。
  3. ChatGPT 登录成功；退出后状态变为未登录；再登录一次。
  4. 填入一个格式错误的 DeepSeek key，看到提示；填入正确的 key，状态变为已配置。
  5. 安装 Cursor CLI 并登录，Agents 页能读到模型列表，其中没有 GPT 系和 Auto。
  6. 对话线程：依次和三条路线上的 agent 对话，换 agent 后新 agent 能引用前面的内容；在对话里记一条记忆，到另一个线程里能检索到。
  7. 接力线程：按「P1 完成线」第 3 条跑完一个真实线程。
  8. Cursor agent 请求运行一条不在白名单里的命令时，弹出审批；拒绝后命令没有执行。
  9. 打开每个页面和每个设置分页，没有报错或空白页；窄屏下能打开侧滑导航。
  10. 停掉本地服务，界面提示断开；重新启动后自动恢复连接。

## 不做

- 多人使用、账号体系、权限分组。
- 看板、项目管理、和聊天软件（Slack、飞书等）的集成。
- 容器或虚拟机沙箱。命令以我自己的系统用户身份运行，这是已知限制。
- 通过 API key 使用 GPT。GPT 只走 ChatGPT 登录。
- Cursor 里的 GPT 系模型和 Auto。
- 使用 Claude 订阅的 token。
- Windows 和 Linux 的支持与测试。代码不刻意绑定 macOS，但不做保证。
- 统计上报和任何遥测。
- 向量数据库。
- 桌面版的代码签名、公证和自动更新。
- P3 之前接入 ChatGPT、DeepSeek、Cursor 以外的 agent。
